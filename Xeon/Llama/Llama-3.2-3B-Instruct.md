# Llama 3.2\n\n## 1. Model Introduction\n\nLlama 3.2 is a collection of pretrained and instruction-tuned generative models released by Meta. This family includes lightweight models designed for efficient deployment across various platforms, providing a balance of intelligence and performance.\n\nKey features of the Llama 3.2 family include:\n\n- **Enhanced Efficiency**: Optimized for high-performance inference on diverse hardware.\n- **Versatile Quantization Support**: Available in various formats including W8A8, FP8, and AWQ to suit different memory and throughput requirements.\n- **Improved Reasoning**: Built upon the foundation of previous Llama generations with refined instruction-following capabilities.\n\nFor further details, please refer to the official [Llama models documentation](https://github.com/meta-llama/llama-models).\n\n## 2. Model Acquisition\n\nYou can access the models on Hugging Face.\n\n| Data Type | Model Card |\n|:---:|:---:|\n| W8A8 | [Llama-3.2-3B-quantized.w8a8](https://huggingface.co/Llama-3.2-3B-quantized.w8a8) |\n| FP8 | [Llama-3.2-3B-Instruct-FP8](https://huggingface.co/Llama-3.2-3B-Instruct-FP8) |\n| AWQ | [Llama-3.2-3B-Instruct-AWQ](https://huggingface.co/Llama-3.2-3B-Instruct-AWQ) |\n\nThe models can be downloaded to local storage using the following command:\n\n```bash\nhf download --resume <MODEL_ID> --local-dir \'path/to/local/dir\'\n```\n\nThen, set `--model-path <LOCAL_MODEL_PATH>` instead of `--model-path <MODEL_ID>` in the `sglang.launch_server` command.\n\n*Note: You may need to log in to your authorized HuggingFace account to access the model files. Please refer to [HuggingFace login](https://huggingface.co/docs/huggingface_hub/quick-start#login).*\n\n## 3. Model Invocation\n\nSGLang exposes an OpenAI-compatible endpoint. First, start the server:\n\n```python\nfrom openai import OpenAI\n\nclient = OpenAI(\n    base_url="http://localhost:30000/v1",\n    api_key="EMPTY",\n)\n\nresp = client.chat.completions.create(\n    model="Llama-3.2-3B-Instruct",\n    messages=[\n        {"role": "system", "content": "You are a helpful coding assistant."},\n        {"role": "user", "content": "Write a Python function that retries a request with exponential backoff."},\n    ],\n    temperature=0.2,\n    max_tokens=512,\n)\n\nprint(resp.choices[0].message.content)\n```\n\n## 6. Benchmarking\n\nOpen another terminal and run the `sglang.bench_serving` command. An example command is provided below:\n\n```bash\npython -m sglang.bench_serving                                 \\\n    --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json   \\\n    --dataset-name random                                      \\\n    --random-input-len 1024                                    \\\n    --random-output-len 1024                                   \\\n    --num-prompts 1                                            \\\n    --max-concurrency 1                                        \\\n    --request-rate inf                                         \\\n    --random-range-ratio 1.0\n```\n\nIn the example command:\n\n- `--request_rate inf` indicates that all requests should be sent simultaneously.\n- `--num-prompts 1` and `--max-concurrency 1` indicate 1 request is sent in this test round; adjust these to test different concurrency levels.\n- `--dataset-name random` selects samples randomly from the dataset.\n- `--random-input 1024`, `--random-output 1024`, and `--random-range-ratio 1.0` settings are for a fixed 1024-in/1024-out token size limit.\n\nPlease adjust settings per your benchmarking scenarios. Detailed descriptions for the arguments of `bench_serving` are available in [this doc](../../base/benchmarks/lm_benchmark.md).\n
