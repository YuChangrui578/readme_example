# Running Llama-3.2-3B on Xeon® with SGLang\n\n## Model Acquisition\n\nYou can access the models on huggingface.\n\n| Data Type | Model Card |\n|:---:|:---:|\n| W8A8 | [RedHatAI/Llama-3.2-3B-quantized.w8a8](https://huggingface.co/RedHatAI/Llama-3.2-3B-quantized.w8a8) |\n| FP8 | [RedHatAI/Llama-3.2-3B-Instruct-FP8](https://huggingface.co/RedHatAI/Llama-3.2-3B-Instruct-FP8) |\n| AWQ | [AMead10/Llama-3.2-3B-Instruct-AWQ](https://huggingface.co/AMead10/Llama-3.2-3B-Instruct-AWQ) |\n\nThe models can be downloaded to local storage by command\n\n```bash\nhf download --resume <MODEL_ID> --local-dir 'path/to/local/dir'\n```\n\n*Note:* You may need to log in your authorized HuggingFace account to access the model files.\nPlease refer to [HuggingFace login](https://huggingface.co/docs/huggingface_hub/quick-start#login).\n\n## Model Deployment\n\nThe BKMs for model service deployment & benchmarking for the supported data types are as follows:\n\n[W8A8](#w8a8)\n\n[FP8](#fp8)\n\n[AWQ](#awq)\n\n---\n\n### W8A8\n\n#### Environment Setup\n\n`Llama-3.2-3B-quantized.w8a8` is supported by official SGLang.\nPlease refer to the `Installation` section in [the official SGLang CPU server document](https://docs.sglang.io/platforms/cpu_server.html#installation).\n\n#### Launch of the Serving Engine\n\nAn example command to launch SGLang server with `RedHatAI/Llama-3.2-3B-quantized.w8a8` would be like:\n\n```bash\nsglang serve                     \\\\\n    --model-path RedHatAI/Llama-3.2-3B-quantized.w8a8   \\\\\n    --trust-remote-code          \\\\\n    --disable-overlap-schedule   \\\\\n    --device cpu                 \\\\\n    --enable-torch-compile       \\\\\n    --host 0.0.0.0               \\\\\n    --tp 1                       \\\\\n    --quantization w8a8\n```\n\nThe `<MODEL_ID_OR_PATH>` can be either the model ID or the path of the pre-downloaded model folder.\n\nPlease read the `Notes` part in the serving engine launching section in [the official SGLang CPU server document](https://docs.sglang.io/platforms/cpu_server.html#launch-of-the-serving-engine) to better understand how to configure the arguments.\n\n#### Benchmarking\n\nOpen another terminal and run the `sglang.bench_serving` command.\n\n```bash\npython -m sglang.bench_serving                                 \\\\\n    --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json   \\\\\n    --dataset-name random                                      \\\\\n    --random-input-len 1024                                    \\\\\n    --random-output-len 1024                                   \\\\\n    --num-prompts 1                                            \\\\\n    --max-concurrency 1                                        \\\\\n    --request-rate inf                                         \\\\\n    --random-range-ratio 1.0\n```\n\n---\n\n### FP8\n\n#### Environment Setup\n\n`Llama-3.2-3B-Instruct-FP8` is supported by official SGLang.\nPlease refer to the `Installation` section in [the \\\\\n    --quantization fp8\n```\n\nThe `<MODEL_ID_OR_PATH>` can be either the model ID or the path of the pre-downloaded model folder.\n\nPlease read the `Notes` part in the serving engine launching supported in [a dev branch](https://github.com/jianan-gu/sglang/tree/cpu_optimized).\n\nYou can pull the docker image if you have access to `gar-registry.caas.intel.com`:\n\n```bash\ndocker pull gar-registry.caas.intel.com/pytorch/pytorch-ipex-spr:intel-sglang-cpu-optimized\n```\n\nOr you can build the image from the Dockerfile:\n\n```bash\ngit clone -b cpu_optimized https://github.com/jianan-gu/sglang.git\ncd sglang/docker\n# May need to add some other (e.g. proxy) settings\ndocker build -t sglang:intel-cpu-optimized -f xeon.Dockerfile .\n```\n\n#### Launch of the Serving Engine\n\nAn example command to launch SGLang server with `AMead10/Llama-3.2-3B-Instruct-AWQ` would be like:\n\n```bash\npython -m sglang.launch_server   \\\\\n    --model-path AMead10/Llama-3.2-3B-Instruct-AWQ   \\\\\n    --trust-remote-code          \\\\\n    --disable-overlap-schedule   \\\\\n    --device cpu                 \\\\\n    --enable-torch-compile       \\\\\n    --host 0.0.0.0               \\\\\n    --tp 1                       \\\\\n    --quantization awq\n```\n\nThe `<MODEL_ID_OR_PATH>` can be either the model ID or the path of the pre-downloaded model folder.\n\nPlease read the `Notes` part in the serving engine launching section in [the official SGLang CPU server document](https://docs.sglang.io/platforms/cpu_server.html#launch-of-the-serving-engine) to better understand how to configure the arguments.\n\n#### Benchmarking\n\nOpen another terminal and run the `sglang.bench_serving` command.\n\n```bash\npython -m sglang.bench_serving                                 \\\\\n    --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json   \\\\\n    --dataset-name random                                      \\\\\n    --random-input-len 1024                                    \\\\\n    --random-output-len 1024                                   \\\\\n    --num-prompts 1                                            \\\\\n    --max-concurrency 1                                        \\\\\n    --request-rate inf                                         \\\\\n    --random-range-ratio 1.0\n```\n\n---\n\n## Benchmarking Argument Guide\n\nIn the example command above:\n\n- `--request-rate inf` indicates that all requests should be sent simultaneously.\n- `--num-prompts 1` and `--max-concurrency 1` indicates 1 request is sent in this test round, can be adjusted for testing with different request concurrency number.\n- `--dataset-name random` is set to randomly select samples from the dataset.\n- `--random-input-len 1024`, `--random-output-len 1024` and `--random-range-ratio 1.0` settings are for fixed 1024-in/1024-out token size limit (realized by truncating or repeating the original sample).\n\nPlease adjust the settings per your benchmarking scenarios. Detailed descriptions for the arguments of `bench_serving` are available via the command:\n\n```bash\npython -m sglang.bench_serving -h\n```\n
